# JSON-профиль Krul версии 4 {#json_protocol_v4}

Этот документ задаёт нормативные изменения wire-контракта Krul v4. Общая
структура запросов, ответов, discovery, ошибок, событий, отложенных команд и
UI-метаданных сохранена из @ref json_protocol_v3. Версия 4 несовместима с v3
по представлению `enum` и должна явно проверяться через `WHOAMI`.

## Версия и встроенные команды

`WHOAMI` возвращает `"protocol_version": 4`. Встроенные команды v4:

- `PING`;
- `WHOAMI`;
- `CMD_LIST`;
- `DESCRIBE`.

`PING` предназначен для частой проверки соединения. Запрос и единственный
допустимый успешный ответ:

```json
{"cmd":"PING","id":42}
{"id":42,"success":true}
```

В отличие от остальных успешных ответов, ответ `PING` не содержит `result`.
Ошибка `PING` использует обычный конверт `id`/`success:false`/`error`.

## Числовые enum

Значение поля типа `enum` во всех payload v4 является знаковым целым `int32`.
Строковые enum из v3 запрещены. Это правило одинаково для JSON, BSON и CBOR,
для параметров, результатов, вложенных объектов, массивов и defaults.

`DESCRIBE` публикует варианты в прежней форме, но `value` теперь число:

```json
{
  "name":"channel",
  "type":"enum",
  "default":0,
  "constraints":{"values":[
    {"value":0,"title":"FDCAN 1"},
    {"value":1,"title":"FDCAN 2"}
  ]}
}
```

`value` — стабильный wire-код. `title` — только человекочитаемая подпись и не
должен отправляться вместо кода. Коды уникальны внутри одного enum-дескриптора.
Добавление нового варианта в конец не меняет существующие коды; перестановка,
удаление или перенумерация существующих вариантов требует новой версии
протокола либо отдельного согласованного изменения контракта.

Пример вызова:

```json
{"cmd":"CAN_SEND","id":7,"params":{"channel":1,"id":256,"data":"demo"}}
```

Командные имена, имена полей и строковые поля остаются строками. Krul v4 не
вводит фиксированные числовые коды команд или стандартных map-ключей.

## Транспорт и форматы

Transport framing остаётся v1: `KRJ1` для JSON, `KRB1` для BSON и `KRC1` для
CBOR, затем `uint32` little-endian длина, payload и CRC-16/CCITT-FALSE.
Максимальный payload — 10 КиБ. Форматы несут одну и ту же модель Krul v4.

CBOR-профиль и его неканоническое кодирование описаны в
@ref cbor_protocol_v4. Переход v3 → v4 не меняет алгоритм CBOR map-тегов.

## Миграция v3 → v4

Клиент обязан:

1. Проверить `WHOAMI.protocol_version == 4`.
2. После `DESCRIBE` хранить `enum.constraints.values[].value` как число без
   преобразования в строку.
3. Показывать `title`, но отправлять соответствующий числовой `value`.
4. Использовать `PING` для heartbeat и принимать успешный ответ без `result`.

Сервер обязан валидировать enum как `int32`, отклонять неизвестные коды и
публиковать числовой default. Одновременный приём строковых v3 enum в сервере
v4 не предусмотрен.
