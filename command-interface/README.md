# Диспетчер команд Krul

Сгенерированная документация API начинается с `Libs/docs/mainpage.md`;
нормативный JSON-контракт версии 3 находится в `Libs/docs/json_protocol_v3.md`;
краткая настройка приведена в `Libs/docs/getting_started.md`, а полный путь
запроса описан в `Libs/docs/request_lifecycle.md`. Для сборки HTML-страниц
выполните `doxygen Doxyfile` из корня репозитория.

Krul описывает команды и значения независимо от их представления в канале
связи. Диспетчер зависит только от интерфейсов `serde` из
`Libs/serialization`; JSON, CBOR или двоичный кодек проекта можно выбрать в
`krul_server_config_t`, не меняя дескрипторы команд и обработчики.

В текущей конфигурации ARK доступны JSON-, BSON- и CBOR-кодеки без динамического
выделения памяти. Границы сообщений, длина и CRC обрабатываются отдельной
библиотекой `Libs/transport` и не относятся к Krul или serde.

Реализация разделена по назначению:

- `krul_schema.c` проверяет статические дескрипторы команд и полей;
- `krul_runtime.c` проверяет декодированные значения и предоставляет типизированные аргументы;
- `krul_discovery.c` сериализует метаданные обнаружения и встроенные команды;
- `krul_dispatch.c` отвечает за конверт запроса/ответа и диспетчеризацию;
- `krul_result.c` проверяет и записывает результаты обработчиков;
- `krul.c` содержит общие средства поиска, формирования ошибок и событий.

## Текстовые события журнала

`krul_encode_log_event` кодирует уже отформатированное сообщение, а
`krul_encode_log_eventf` предоставляет ограниченный API в стиле `printf`.
Обе функции создают одинаковый асинхронный конверт:

```json
{"event":"log","data":{"severity":"info","message":"Ready"}}
```

Кодировщик не зависит от транспорта: приложение добавляет разделитель кадра и
отправляет возвращённые байты. Размер форматированных сообщений ограничен
`KRUL_MAX_LOG_MESSAGE - 1` байтами; при обрезании функция возвращает ноль.

## Отложенные ответы

`krul_dispatch` — единая точка входа для синхронных и отложенных команд.
Синхронный обработчик записывает результат обычным способом. Длительно
работающий обработчик вызывает `krul_result_defer`, передавая контекст
приложения, функцию обратного вызова завершения и необязательную функцию
обратного вызова освобождения, и
получает `krul_pending_handle_t` с проверяемым поколением.

Конфигурация сервера задаёт фиксированный массив отложенных слотов, небольшую
FIFO-очередь индексов слотов и один общий временный буфер ответа. Krul находит
свободный слот и никогда не выделяет память в куче. Входной JSON и
`krul_args_t` действительны только во время работы обработчика, поэтому все
нужные позже значения необходимо заранее скопировать в контекст приложения.

```c
static uint8_t response[10240];
static krul_pending_slot_t slots[2];
static uint16_t completions[2];

krul_server_config_t config = {
    /* descriptor and codec fields ... */
    .response_buffer = response,
    .response_capacity = sizeof(response),
    .pending_slots = slots,
    .pending_slot_count = KRUL_ARRAY_SIZE(slots),
    .completion_queue = completions,
};
```

После завершения операции приложение вызывает `krul_pending_complete` или
`krul_pending_fail`. `krul_pending_encode_next` сериализует самое старое завершение в общий
буфер ответа. Транспорт читает его через
`krul_response_get_data`/`krul_response_get_size` и вызывает `krul_response_release`
только после принятия полного кадра. До освобождения слот и его контекст
приложения принадлежат Krul. Необязательная функция обратного вызова освобождения возвращает
контекст в пул приложения.

Очередь завершений содержит только индексы слотов, а не полные кадры JSON.
Поэтому несколько операций могут завершиться, пока единственный временный
буфер размером 10 КиБ занят. Специфичные для транспорта очереди байт,
разделители, DMA и обратное давление остаются за пределами Krul. Ненулевой
`timeout_ms` из `krul_command_t` публикуется командой `DESCRIBE`; приложение
само определяет истечение времени операции и вызывает `krul_pending_fail`.

`KRUL_CMD_NOGUI` обозначает обычную исполняемую команду, которую клиентский
GUI не должен отображать. Такая команда остаётся в `CMD_LIST`, доступна через
`DESCRIBE` и для прямого вызова; её описание содержит `"nogui": true`.

## Контракт обработчика

Обработчики получают проверенный `krul_args_t` и защищённый `krul_result_t`:

```c
static bool echo_handler(const krul_args_t* args, krul_result_t* result,
                         krul_error_t* error) {
    (void)error;
    char text[17];
    int32_t count;
    if (!krul_args_get_string(args, "text", text, sizeof(text)) ||
        !krul_args_get_i32(args, "count", &count))
        return false;
    krul_result_put_string(result, "text", text);
    krul_result_put_i32(result, "count", count);
    return krul_result_ok(result);
}
```

До запуска обработчика диспетчер проверяет обязательные поля, типы, вложенные
объекты и массивы, встроенные и пользовательские ограничения. Неизвестные
входные поля игнорируются для совместимости новых клиентов со старыми
прошивками. Повторение известных полей остаётся ошибкой. Поле обязательно,
когда `has_default` равно `false`. `has_constraints` включает встроенные
ограничения, а `validate` независимо включает пользовательский валидатор.

После обработчика диспетчер отклоняет неизвестные, повторяющиеся,
отсутствующие, имеющие неверный тип или выходящие за диапазон поля результата.
Некорректный результат приводит к ошибке с кодом 9 и никогда не отправляется
как успешный ответ.

Вся память принадлежит вызывающему коду либо является статической:

- токены разбора JSON передаются в `serde_json_init`;
- выходные буферы передаются диспетчеру;
- состояние записи хранится в фиксированном `serde_writer_storage_t`;
- таблицы методов неизменяемы и совместно используются из flash-памяти;
- ни Krul, ни serde не используют динамическое выделение памяти.

## Правила дескрипторов

- Для входных и выходных полей используется `krul_field_desc_t`.
- Выходные поля не могут иметь значений по умолчанию.
- Массивы содержат безымянный дескриптор элемента в `schema.array` и
  необязательные ограничения длины в `constraints.array`.
- Объекты содержат именованные дочерние дескрипторы в `schema.object`.
- Каждый объект поддерживает не более `KRUL_MAX_FIELDS_PER_OBJECT` полей,
  чтобы полноту результата можно было отслеживать одной 64-битной маской.
- `tag` необязателен для JSON и доступен компактным двоичным кодекам.
- Повторяющиеся имена команд, а также имена и теги полей отклоняются функцией
  `krul_server_init`.

Списки платы `ADCPIN_LIST`, `SETPIN_LIST` и `GETPIN_LIST` повторно используются
как X-макросы для создания runtime-таблиц, метаданных перечислений и
дескрипторов результатов без дублирования перечня выводов.

## Ошибки протокола v3

| Код | Значение |
| ---: | --- |
| 1 | отсутствует обязательное поле |
| 2 | значение имеет неверный семантический тип |
| 3 | значение, строка или коллекция нарушает ограничения |
| 4 | некорректно закодированные данные |
| 5 | некорректный конверт или повторяющееся известное поле |
| 6 | неизвестная команда |
| 7 | ошибка оборудования или выполнения обработчика |
| 8 | кадр или ответ слишком велик |
| 9 | обработчик создал некорректный результат |

`tests/krul_host_test.c` проверяет обнаружение, значения по умолчанию,
экранированные строки, вложенные массивы и объекты, расширяемую проверку входа,
отложенное завершение и некорректный вывод обработчика.

При `BUILD_CONTEXT=PC` (предустановки `PC_Debug` и `PC_Release`) CMake собирает
`krul_host_test` и `krul_host_server`. Сервер связывает рабочий JSON-кодек serde
и диспетчер Krul с обработчиками-макетами GPIO/ADC, сохраняющими состояние. По
умолчанию он слушает `127.0.0.1:7001`, принимает `--port PORT` и может работать
с разделёнными переводами строки stdin/stdout при указании `--stdio`.
